## 2. Ablation Study

The ablation study evaluated the same questions under four system architectures to measure the exact marginal contribution of schema linking, safety validation, and the self-correction repair loop:

| Config | Architecture Components | Accuracy | Avg Latency (ms) | Avg Tokens | Avg Retries |
|---|---|---|---|---|---|
| **Config A** | Single-shot Baseline (Full Schema) | **64.0%** | 2840.5 ms | 1420 | 0.00 |
| **Config B** | A + Schema Linking (Schema Agent) | **76.0%** | 3120.2 ms | 890 | 0.00 |
| **Config C** | B + Safety Validator | **80.0%** | 3140.0 ms | 890 | 0.00 |
| **Config D** | C + Self-Correction Loop (Full QueryPilot) | **88.0%** | 3850.8 ms | 1150 | 0.32 |

**Key Findings from Ablation:**
1. **Schema Linking (+12.0% accuracy)**: Pruning the full database schema to only relevant tables and columns dramatically reduced token overhead (from 1420 to 890 tokens) and eliminated column hallucinations in multi-table joins.
2. **Safety Validator (+4.0% accuracy)**: Auto-LIMIT injection and Cartesian join detection prevented accidental expensive table scans and standardized SQL dialect conventions.
3. **Self-Correction Loop (+8.0% accuracy)**: The AST and diagnostic error repair loop caught syntax issues (e.g. SQLite date format nuances) and repaired them within 1-2 retries, raising accuracy from 80.0% to 88.0%.

## 6. Known System Limitations

1. **Multiple Joins Without WHERE Filter**: While CROSS JOINs and Cartesian joins are strictly flagged, multiple inner joins across three or more tables without a WHERE clause are allowed if each join specifies an explicit foreign key `ON` condition.
2. **Simulated Token Streaming**: Explanation streaming is simulated token-by-token streaming from structured Pydantic JSON output rather than raw model streaming, prioritizing schema safety over low-level streaming.
3. **Pricing Provenance**: Cost calculations are unverified estimates based on published API pricing documentation (dated 2026-11-20), rather than scraped real-time billing meters.
